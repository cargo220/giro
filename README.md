# giro

카메라 한 대로 물류 상자의 종류를 가리고, 그 결과로 로봇 두 대가 분류와 적재를 수행하게 만드는 머신비전 프로젝트다. 1차는 카메라만으로 판별하고, 2차는 그 판별 결과를 로봇 동작까지 잇는다.

## 배경

아마존형 스마트 물류를 만드는 회사를 가정한 과제다. 카메라로 물류를 종류별로 나누고 적재하는 방안으로 투자 심사를 받았고, 관심을 보인 A사가 자사 물류상자를 판별·적재하는 로봇 시스템 개발을 요청했다.

조건은 로봇 두 대와 카메라 한 대다. 6주 차에 중간 시연, 12주 차에 최종 심사다. 슬라이드의 시연 날짜는 아직 `xx월 xx일`이라, 일정이 정해지기 전까지 주 차만 기준으로 둔다.

## 1차 — 비전

중간 시연 전에 A사 평가자에게 카메라만으로 상자를 종류별로 보여 준다. 로봇은 이 단계에서 움직이지 않는다.

풀어야 할 질문:

- 카메라로 움직이는 물체를 어떻게 찾아낼 것인가
- 오픈소스로 물체 판별 알고리즘을 어떻게 만들 것인가

끝나야 하는 일:

- 비전으로 물체를 인식하는 과정을 구현한다
- 카메라로 물체의 색을 가려 종류를 나눈다

## 2차 — 비전과 로봇

1차 시연이 통과한 뒤의 과제다. 시나리오상 A사는 6주 차 시연을 보고 30억 원 투자를 결정했고, 12주 차 최종 계약 전까지는 판별 결과로 상자를 실제로 분류하고 적재할 수 있어야 한다.

풀어야 할 질문:

- 카메라에서 받은 정보를 로봇에 어떻게 넘길 것인가
- 그 정보에 따라 로봇 동작이 어떻게 달라지는가
- 분류 로봇과 적재 로봇의 타이밍을 어떻게 맞출 것인가

끝나야 하는 일:

- 비전과 로봇을 한 시스템으로 잇는다
- 비전 결과로 로봇이 정해진 작업을 수행하게 제어한다

## 해법의 여지

판별 방식, 두 로봇의 역할, 둘 사이의 타이밍은 이 저장소에서 직접 정한다. 색 임계값 하나만으로 끝내는 구성은 이 과제가 요구하는 해법이 아니다. 알고리즘과 통신 방식은 구현하면서 고르고, 고른 이유는 코드와 함께 이 문서에 보탠다.

## 시스템

```
OpenMV Cam H7 R2
        │
        ▼
   상자 종류 판별
        │
        ├──────────────┐
        ▼              ▼
   분류 로봇        적재 로봇
```

1차에서는 판별까지만 동작한다. 2차에서 같은 판별 결과가 두 로봇의 동작과 순서를 정한다.

## 판별 대상

종류는 색 다섯 가지다. 파랑, 초록, 빨강, 보라, 노랑.

1차는 이 다섯 색을 서로 가르는 일이다. 스크립트는 `camera.py`이고, 이름은 LAB 밝기가 아니라 블럭 면의 색상 각도로 정한다. 노출은 바닥이 아니라 그 면에 맞추고, 색수차가 도는 가장자리는 판별에서 뺀다. 기준은 `description.md`에 있다. 2차는 그 다섯 결과로 분류 로봇과 적재 로봇의 동작을 정한다.

## 카메라 — OpenMV Cam H7 R2

제출용 카메라는 OpenMV Cam H7이다. 센서 리비전은 R2라 이미지 센서가 ON Semi MT9M114다. 초기형 H7의 OV7725가 아니고, 외장 SDRAM 32 MB와 USB High Speed가 있는 H7 Plus도 아니다. RAM 1 MB인 기본 H7이다. `camera.py`는 이 한도 안에서만 동작하게 작성한다.

연습용으로 이 PC에 연결된 보드는 OpenMV Cam RT1062다. USB는 `37c5:1060`, 내장 FAT은 4 MB, 시리얼은 `/dev/ttyACM0`이다. RT1062의 고해상도, 외장 SDRAM, Wi-Fi, 이더넷은 쓰지 않는다.

아래 표는 이전에 H7을 OpenMV IDE의 COM26으로 읽었을 때의 값이다.

| 항목 | 측정값 |
| --- | --- |
| 보드 | OpenMV Cam H7 (STM32H743), 센서 리비전 R2 |
| 센서 | ON Semi MT9M114 (칩 ID 0x2481) |
| 펌웨어 | 4.1.1 — IDE가 자기보다 오래됐다고 표시 중 |
| USB | Full Speed 12 Mb/s, VID 1209 / PID ABD1, 시리얼 347F356F3430 |
| 포트 | COM26, 내장 플래시가 F:로 마운트 |
| 지금 프레임 | 320×240, 약 22 fps (`10_helloworld.py` 실행 중) |

22 fps는 그때 돌리던 스크립트의 속도다. 센서가 낼 수 있는 최대 프레임은 아니다.

### 프로세서와 메모리

STM32H743, Cortex-M7 480 MHz (1027 DMIPS), 하드웨어 JPEG 코덱.

내장 SRAM은 1 MB이고 외장 SDRAM은 없다. 내장 플래시 2 MB는 부트로더 128 KB, 사용자 FAT 128 KB, 펌웨어 약 1.75 MB로 나뉜다. PC에 보이는 F:가 그 128 KB다. 지금 그 안에는 공장 기본 `main.py`(파란 LED 두 번 깜빡임)와 `README.txt`만 있다. microSD는 꽂혀 있지 않다.

프레임 버퍼가 이 1 MB 안에 있어야 하므로, 센서 화소가 많아도 한 번에 다루는 해상도는 아래가 한도다.

| 형식 | 한도 |
| --- | --- |
| 흑백 | 640×480 |
| RGB565 | 320×240 (그 위는 JPEG) |
| JPEG | 흑백·컬러 모두 640×480 |

밝은 환경에서 QVGA 이하는 수십 fps가 나오고, 읽기 창을 줄이면 더 올라간다. 1차 판별을 실시간으로 돌리려면 RGB565 320×240 안에 두거나, 더 큰 화면이 필요하면 JPEG로 받는 쪽을 먼저 저울질한다.

### 센서

MT9M114는 1/6인치 롤링 셔터다. 유효 화소는 약 1296×976 (1.26 MP)이고, 자동 노출과 화이트밸런스를 포함한 ISP가 들어 있다. R2 기본 렌즈는 초점거리 2.1 mm, F2.0이다.

롤링 셔터라 상자가 빠르게 지나가면 프레임 안에서 형태가 밀릴 수 있다. 노출과 판별 창 크기는 실제로 흐르는 속도를 보고 맞춘다.

### 저장장치

USB는 가상 COM과 대용량 저장장치가 같이 붙는다. microSD는 SD 2 GB, SDHC 32 GB, SDXC 2 TB까지 쓸 수 있다. 카드가 있으면 `/sdcard`가 부팅 드라이브가 되고, 없으면 `/flash`(지금 F:)가 된다. 사용자 FAT이 128 KB뿐이라, 스크립트가 늘거나 이미지를 남기면 카드를 꽂는 쪽이 먼저다.

### 입출력

헤더 핀은 P0–P9, 열 개다. 출력은 3.3 V, 입력은 5 V를 허용한다. 핀당 25 mA, 헤더 합계 120 mA다. P6은 ADC나 DAC로 쓸 때 3.3 V만 허용한다.

| 기능 | 핀 |
| --- | --- |
| UART1 | P1 / P0 |
| UART3 | P4 / P5 |
| I2C2 | P4 / P5 |
| I2C4 | P7 / P8 |
| SPI2 | P0–P3 |
| FDCAN2 | P2 / P3 |
| ADC · DAC | P6만 |
| PWM | P4–P9 |

TIM1은 센서 픽셀 클럭이라 PWM에 쓸 수 없다. 보드에는 RGB LED와 850 nm IR LED 두 개가 있다. LiPo 커넥터는 있지만 충전 회로는 없다. VIN과 배터리 단자가 묶여 있어서 둘을 동시에 연결하지 않는다.

2차에서 로봇으로 판별 결과를 넘길 때는 이 핀 구성 안에서 고른다. UART, I2C, SPI, CAN이 핀을 나눠 쓰므로, 로봇 두 대의 통신을 정한 뒤에 핀을 고정한다.

## 아직 정하지 않은 것

- 로봇 기종, 그리고 카메라와 로봇 사이 통신
- 컨베이어나 상자가 지나가는 방식
- 6주·12주 시연의 실제 날짜
- 펌웨어 4.1.1을 IDE에 맞게 올릴지
- 스크립트와 기록을 둘 위치 (`/flash` 128 KB 또는 microSD)
